# Experimental cooperative start boundary

`CooperativeDispatcher` is isolated and not wired into the production dispatcher or MongoDB runner. Its injected runner waits for admission, then calls `finalize()` synchronously, immediately before its first session or transaction operation, with no intervening await. A missing batch means no work may start. The runner must not start session work before finalization, call it more than once, or retain it beyond its own lifetime. These obligations are cooperative, not enforceable against an untrusted runner.

Until finalization, members remain dispatcher-owned and compactable: cancellation/deadline removes them and releases their reservation. Finalization rechecks elapsed deadlines synchronously, selects distinct keys, and seals the remaining members atomically in the JavaScript event loop. Arrivals while admission is waiting can join the candidate group. After finalization cancellation or deadline reports unknown and does not remove the member; batch capacity and bytes remain reserved until the runner has returned after cleanup. A runner rejection after finalization retains capacity indefinitely, failing closed. Shutdown cancels pre-start members and prevents subsequent finalization; after finalization its timeout reports unknown but does not release an owned batch until cleanup. The runner must settle the batch and return only after cleanup has completed; if cleanup cannot be confirmed it must reject or remain pending.

The existing `runMongoGroup`/`executeGroup` currently acquires its own batch hold, so it cannot be directly injected into this dispatcher. An isolated `TransactionAdmission` prototype now supplies FIFO, count/byte-bounded process-local admission. Count and bytes include the owner; cancellation and absolute epoch-millisecond deadlines apply only while waiting. Shutdown rejects waiters and drains only when the owner releases. The idempotent release function belongs to the granted owner and **must be called only after confirmed session cleanup**; the mutex cannot enforce this cooperative obligation. Unconfirmed cleanup must leave the lease held, possibly indefinitely. The test-only borrowed-hold harness exercises this contract against MongoDB, but is not production wiring. Production integration still requires a shared-ownership-compatible runner, lifecycle/error handling, configuration, and production-path integration tests. This prototype is not a distributed lock and does not establish transaction outcomes.
